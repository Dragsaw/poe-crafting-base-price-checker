# PRD Conformance Review — `{components.trade-link}` Spot-Check

- **Lens:** PRD conformance (memlog 54), scoped to one addition per memlog 154
- **Under review:** `{components.trade-link}` as added to `DESIGN.md` and `EXPERIENCE.md` (memlog 146–153)
- **Authority on deliberate departures:** `.memlog.md`
- **Source of truth:** `docs/prds/prd-poe-crafting-base-price-checker-2026-09-12/prd.md` (rev 8) + `addendum.md` (rev 5)
- **Prior full pass:** `review-prd-conformance.md` (not redone; this is additive)
- **Date:** 2026-09-13

## Verdict

The addition is sound on the two things it visibly touches: it correctly reuses the PRD's own vocabulary (SM-1 already names "the trade site," so no synonym is introduced), it is excluded from the one row-type — the tombstone — where FR-15's exclusion logic says it should never appear, and memlog 152's "no write path" claim against AD-15/AD-21 is correct as far as it goes: a `target="_blank"` outbound link is not a write and does not touch page state. But the feature's premise depends on a field the PRD's data model never defines, and the spines' own justification cites the wrong architecture decision for the risk that actually applies. **The one blocking item is schema, not view:** rendering a working trade-site link requires a persisted search identifier that no artifact in FR-33's fetched set, no field in §3's *Price Observation*, and no field in `WEIGHTS-FILE-SCHEMA.md` currently carries — this is new sync-side surface of the same kind the Accepted Tier field was (memlog 136), and it is already flagged with `[NOTE FOR UX]` and routed to `bmad-correct-course`, which is the right call and should be treated as a precondition of build, not a footnote. Separately, the spines defend the link against AD-15/AD-21 (no write path) but never engage with the architecture decision whose literal wording is closer to the risk here — FR-33's "without a runtime call to pathofexile.com, which is forbidden (AD-15, AD-25)." The distinction (a user-driven navigation the app does not depend on, versus a fetch the app's own rendering depends on) is real and defensible, but it is asserted nowhere in either spine or the memlog, which leaves the feature's compliance with that clause resting on an inference this review had to reconstruct rather than one the spines stated. A third item is softer: SM-1 is literally "the trade site stays closed mid-session," and this is the page's first and only affordance whose entire purpose is sending the player back to it — plausibly still consistent (it serves UJ-3/UJ-4 drill-down/trust-check rather than the habitual price-checking SM-1 targets), but neither document acknowledges the metric it sits closest to.

**Counts.** 1 HIGH (schema dependency — already disclosed, needs correct-course to actually run before build), 1 MEDIUM (wrong/missing AD citation for the pathofexile.com-call risk), 1 LOW (SM-1 tension unacknowledged), 1 LOW (search-id staleness/expiry has no owner). No Glossary synonym violations found.

## Findings

| # | Severity | Requirement(s) | Finding |
|---|---|---|---|
| T1 | HIGH | §3 *Price Observation*, FR-33 (the eight fetched artifacts), FR-27/29 (Weights File schema) | The link's click target needs a durable trade-site search identifier to navigate to. Nothing in the PRD's data model carries one today: `Price Observation` (§3) is stamped with observation time, league and exchange observation — not a search id; the eight artifacts FR-33 lists (`dataset.json`, `sync-report.json`, `weights.json`, `recipes.json`, `tracked.json`, `config.json`, two catalogue files) have no such field in any PRD description; `WEIGHTS-FILE-SCHEMA.md` is producer-owned and out of scope for this. This is the same shape of gap the Accepted Tier field was before spine rev 2 absorbed it (memlog 136) — a UX need surfacing a missing contract field. **Already correctly identified**: memlog 149 and EXPERIENCE.md line 627 carry `[NOTE FOR UX]` routing this to `bmad-correct-course` "once the syncer/schema side is touched." This finding exists only to make explicit that the routing is a precondition of shipping the feature, not an optional follow-up — a builder cannot implement `{components.trade-link}` correctly without either that field existing or a decision that `web` derives the search independently (which runs into T2 below). |
| T2 | MEDIUM | FR-33 ("without a runtime call to pathofexile.com, which is forbidden (AD-15, AD-25)"), AD-15 | Memlog 152 clears the link against AD-15/AD-21 ("does not add a write path... does not touch page state") but never addresses the architecture text whose wording is the closer match: FR-33 states a runtime call to pathofexile.com is *forbidden*, full stop, and cites AD-15 for that prohibition. A `target="_blank"` navigation the user triggers is a different thing from a fetch/XHR the app's own rendering depends on — the former is why `web` can't independently mint a fresh search id at view time (reinforcing T1: the id must come from a `sync`-side request that already happened, not a live call `web` makes), the latter is what FR-33's catalogue files exist to avoid. That distinction is real, but it is asserted nowhere in `DESIGN.md`, `EXPERIENCE.md`, or the memlog trail — the spines cite the correct-but-adjacent AD-15/AD-21 write-path argument and stay silent on the more literally-applicable clause. A one-line note ("this is a user-navigated outbound link, not a runtime call the page makes on its own behalf, so FR-33's prohibition does not reach it") would close the gap and also make explicit why the search id must be `sync`-sourced rather than `web`-computed. |
| T3 | LOW | §8 SM-1 ("The trade site stays closed mid-session... Validates FR-1, FR-2, FR-8") | `{components.trade-link}` is the page's first and only outbound navigation, and its entire purpose is returning the player to the trade site — the exact behavior SM-1 names as the thing this product is meant to end. The two are plausibly reconcilable (SM-1 is about *habitual* price-checking the ranked list replaces; the link serves UJ-3's drill-down and UJ-4's trust-check, an occasional verification rather than a return to the old workflow), but neither spine nor the memlog trail states that reconciliation — the tension is simply not mentioned. Worth one sentence recording that the link is deliberately for verification, not a regression toward pre-tool behavior, so a future reader doesn't read the feature as quietly undermining a named success metric. |
| T4 | LOW | FR-33/AD-15 (no live trade-site dependency), §3 *Price Observation* | If the persisted search id is itself something the trade site's own backend can expire or invalidate (a plausible behavior for a third-party search-session id), no requirement anywhere addresses what the link does with a stale id — a click that opens a dead or empty search page. This is downstream of T1 (it can't be answered until the field exists) and is minor, but worth folding into the same `bmad-correct-course` pass rather than discovering it after the field is defined. |

## Confirmed non-issues

- **No Glossary synonym introduced.** "Trade site" is the PRD's own term — SM-1 uses it verbatim ("The player stops opening the trade site to price-check") — so the spines' reuse of "trade site" for `{components.trade-link}`'s destination is not a new synonym; it is the PRD's own vocabulary.
- **Tombstone exclusion is correct.** Memlog 150's rule (never on `{components.tombstone-band}`) matches FR-15/AD-23: a `pruned` entry is excluded from both the sync workload and the ranking, and a link inviting a fresh trade-site look at a dead entry would contradict the reason it was pruned. No FR requires or implies the opposite.
- **AD-15/AD-21 write-path claim holds.** A `target="_blank" rel="noopener"` link that does not touch page state and originates no request the app depends on is correctly not a write path; NFR-5 (one writer per file) and AD-21 (hand-owned `tracked.json`) are unaffected.
- **NFR-10 / "no fourth ink" (memlog 86/147/148) is respected.** The glyph carries no semantic color and no new ink class; the override is scoped narrowly and doesn't reopen the argument it overrides, as memlog 147 claims.
