The panel sits flush under its row: the row keeps its 3px sepia open marker — bled into the frame's 24px gutter, so no column moves when a row opens — and its bottom rule is promoted to rule-strong, which is the panel's top edge, so there is no double rule at the join. Each Combination is two lines under one hairline: line one is the figure (Combination, Price State with its glyph and its word, price or money phrase, listing sample count), line two is the evidence (the note, then both labelled clocks in their own cells). Line two is always present, so the rows scan evenly down the panel, and it holds its text in full — nothing in an expansion ellipsises, because nothing sits beneath a combination row to resolve a truncation. Its type role sets an absolute 20px line height, so a note long enough to wrap grows the row by exactly one 20px band and the 48 + 20n arithmetic stays literally true. All four Price States are shown, not-yet-synced in all three reasons; never-synced leaves both age cells empty rather than filling them. Two below-threshold entries are shown and marked, and one is a real figure too small to print at 2dp, so it reads < 0.01 rather than 0.00.

The Provenance mark is on the row, not in the panel, and this specimen is where that rule is visible. The open row carries prior only once; no combination row repeats it. Every entry in this panel shares the row's (Item Class, recipe) pair, so it carries that same label by construction — ten identical marks would discriminate nothing, which is the failure FR-11 exists to prevent, one surface further down. One label per pair (AD-10); a recipe switch swaps it silently.

The trade link is keyed on stored data, never on Price State, and the spread here is the proof. Seven rows carry the ↗ and three do not. It is present on every priced row, on the no-listings row — nobody is asking today, but a search did run — and, tellingly, on the no-exchange-rate row, where a search ran in the active league and only the conversion failed. It is absent on never-synced (no search was ever issued, so no id exists), on league-mismatch (an id exists but points into last league's search, which is the stale answer honest-empty prevents), and on this unresolvable row, which was caught offline against the committed catalogue before any request. It is never drawn on a tombstone. Absent means absent: the cell is blank, not greyed and not disabled-looking.
