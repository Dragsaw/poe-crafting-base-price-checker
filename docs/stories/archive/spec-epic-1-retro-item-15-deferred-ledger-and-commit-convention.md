## Intent

**Problem:** Epic 1 retro item 15 (`docs/stories/epic-1-retro-2026-09-26.md:154`, sprint-status id `epic-1-retro-item-15-process-the-build-skill-appends-every-sp`) found two process gaps. First, an agent sometimes records carved-out work only in a spec's own prose (Implementation Notes, Design Notes, an "Agent decision") and never appends it to `docs/stories/deferred-work.md`, so the ledger misses it (R-3 upstream; story 1.7's progress-loss carve-out was only added to the ledger later, by a separate action item). Second, the `feat(pkg): story 1.N …` commit-subject convention that stories 1.5–1.11 followed was never written down (R-6), so nothing tells an agent or a human to keep using it.

**Approach:** Close both gaps as process fixes, not code:

- Add a `deferred-ledger-audit` review layer to the `bmad-build` and `bmad-build-auto` skills, via this repo's `_bmad/custom/bmad-build.toml` and `_bmad/custom/bmad-build-auto.toml` override files (merge rule: new `id` in a `[[workflow.review_layers]]` / `[[workflow.oneshot_review_layers]]` array appends). The layer's instruction: read the spec being reviewed in full, read `docs/stories/deferred-work.md` in full, and report one finding for every piece of work the spec records as carved out, deferred, "not made here", or still owed that has no matching `deferred-work.md` entry naming that spec as `source_spec`. This runs inside the existing review step, which always precedes this workflow's one commit (`step-05-present.md`'s "Commit and Complete", or `step-oneshot.md`'s "Commit", or `bmad-build-auto`'s step-04 §Commit) — so a finding it raises is fixed (append the missing ledger entry) before that commit, landing in the same commit as the change that carved the work out. Give the dispatch-route layer `{claims_file}` (the spec path) and the oneshot layer `{spec_file}` — both already resolve to the spec being reviewed.
- Enforce the commit-subject convention with a `commit-msg` git hook (`.githooks/commit-msg`, a Node script) rather than prose alone. It checks: the subject matches `type(scope): description` or `type: description` with a known Conventional Commits type; the subject has no trailing period; and, only when the type is `feat`/`fix`/`test` **and** the scope is a known package (`contracts`, `core`, `sync`, `web`), the description names a story (`story <epic>.<number>`) or a retro item (`retro item(s) <n>`) — a `docs`/`chore` commit or one with no package scope is exempt. On failure it prints one reason and the exact fix, exits 1, and blocks the commit; the agent or human fixes the subject and commits again. `package.json` wires a `prepare` script (`tools/setup-git-hooks.mjs`) that points git at `.githooks` on `pnpm install`, doing nothing outside a git repository and never overwriting a `core.hooksPath` a developer already set to something else. `AGENT-WORKFLOW.md`'s "Commit conventions" section shrinks to a pointer at the hook plus the one-sentence rule, instead of restating the grammar and examples — the hook is the source of truth and a restated copy would drift from it.
- Human decision 2026-09-26: rewrite the `deferred-ledger-audit` review-layer prompt text added to `_bmad/custom/bmad-build.toml` and `_bmad/custom/bmad-build-auto.toml` with the `asd-ste100` skill (Strict mode — it is an inter-agent instruction), so a context-free reviewing subagent cannot misread it.

Nothing here is irreversible, and no change touches application code, `data/`, or a package's runtime behavior. The hook only gates the local `git commit` step.
