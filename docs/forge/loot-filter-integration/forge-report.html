Crafting-base loot filter

Bring the app's knowledge of what to pick up into the Path of Exile 2 loot filter, starting from a FilterBlade filter.

Outcome: hardened. The direction is a stub filter that imports a file generated by the app, then the FilterBlade export. The decisions are now in PRD revision 35 (FR-35 to FR-37) and spine revision 46 (AD-15, AD-31). An in-game test verified the layering.

How it works

  • You write a stub filter once and select it in the game: Import "crafting-bases.filter" Optional, then Import "<FilterBlade export>.filter".
  • The web view generates crafting-bases.filter with your current Payout Threshold and Craft Recipe. You download it each session, use Chromium's "ask where to save" to overwrite the old file, and reload the filter in the game.
  • The file has only Show blocks and no Continue. The first matching block wins, so for the items the app ranks, the app's style is final. Everything else falls through to FilterBlade unchanged.

  • EV > 0 is the cutoff. The Payout Threshold is not reused as a cutoff.
  • Craft-worthy bases are the raw entries of tracked.json, and you curate them. The filter must use BaseType, because the app's classes are split by attribute.
  • The app wins. It overrides FilterBlade's per-base styling, and that is accepted.
  • Quiet styles. Each purpose has one style, and the styles reuse NeverSink's color meanings.
  • Delivery is a download with "ask where to save". AD-15 needs a clarification that a download you start yourself is permitted.
  • Added during the session: a raw entry for Sacrificial Regalia. tracked:check passes.

Rejected, and why

  • FilterBlade preset module. It has no schema, it needs a UI bot, and the bot would hold a second copy of the dial that drifts.
  • Manual paste. Error-prone at one refresh per session. Kept only as a fallback.
  • A generated file that imports FilterBlade. It makes each download a single point of failure.
  • Skipping the bases that NeverSink highlights. It couples the app to NeverSink's file format and relies on syntax that is not verified.
  • Continue to make the style additive. FilterBlade's hide layer hides the item again.
  • File System Access write. It is a real write path, so it needs an AD-15 amendment. Deferred.
  • Runeforged and Runemastered variants. They never drop naturally, so they need no pick-up rule.
  • Upload to the PoE account. GGG is "currently unable to process new applications", so the app cannot get an OAuth client. It would also break AD-15. The API does support PoE 2. All this to save one dialog.

Weak points that survived

  • Stale file. If the download is saved under the wrong name, the stub loads last session's file without a warning. An optional freshness marker could catch this.
  • Lost nuance. Inside ranked classes, NeverSink's per-base highlights are replaced by the app's style.
  • Jewel EV. It charges a transmute that is never used. Accepted, because the price is negligible.
  • Weak or stale figures go in unmarked. On the ground, an estimated figure looks the same as a measured one, so SM-C4's guard only works in the view.
  • An Unrankable class loses its highlights until the weights data recovers. The signal for this is the Unrankable count in the view.
