Curating tracked.json

The idea started as "a cheap web page for editing tracked.json, with full UI". It ended as: judge in the web view, edit through an agent skill.

Forged 2026-09-26 · outcome Hardened

The workflow that survived

Judge in the web view (Epic 2: 2.5 · 2.6 · 2.8) → Tell the agent the edit → tracked:lookup → edit data/tracked.json → tracked:check → you commit

Locked decisions

  • No editor code goes into packages/web. Work on curation tooling can't regress the ranking page.
  • You judge the list in the planned Epic 2 view, which already has the price data. Nothing new is added to it.
  • Edits and first-version seeding go through Claude Code with a skill at .claude/skills/tracked-json/SKILL.md. The skill follows the AGENT-WORKFLOW reporting rule and applies FR-22's Accepted Tier rule.
  • The scripts are read-only sync commands in Node/TS: pnpm tracked:lookup stat|base|class|tiers and pnpm tracked:check. There's no new package and no Python.
  • The page and the tooling stay local. Nothing new is published, and the PRD is unchanged.

Rejected, and why

  • An editor inside the deployed app. It conflicts with AD-15, AD-3 and PRD §4.5/§7.1, and would need a PRD edit.
  • An editor inside packages/web, fenced by a separate entry point. It breaks the strict-separation lock.
  • A packages/curate local page with a Vite write endpoint. Deferred. It would duplicate Epic 2's judging view without the prices, and it can't import web. Revisit if a curation pass after Epic 2 needs something the view and the skill together can't give.
  • A standalone console curator. Its UX is no better than the agent working with scripts.

Weak points that survived

  • The cross-file checks are Story 3.3, still in backlog. Until it lands, tracked:check is schema-only and misses band edge-alignment and overlap errors, which are the ones seeding is most likely to make.
  • "Full UI support" has been traded away for now. The whole bet rests on Epic 2's view being enough to judge the list.
